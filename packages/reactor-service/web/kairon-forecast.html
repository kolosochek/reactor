Kairon · агент прогноза

Прототип DEV-1364 · синтетический проект Rivergate

Как это работает

  1. kairon.baseline: сервис читает активный прогноз и утверждённый бюджет (обещание инвесторам) и считает оба через evaluate.
  2. kairon.proposeVariants: LLM отвечает по строгой JSON-схеме (коды строк и открытые месяцы заданы перечислением). Патч, который трогает закрытый месяц, возвращается LLM с ошибкой.
  3. kairon.scoreVariants: каждый патч применяется детерминированно и считается сервером Kairon. Отказ сервера показывается как результат варианта.
  4. kairon.explainVariants: LLM объясняет ранжирование. Цифры в тексте подставлены из ответов evaluate.

Этап 5: разговор

  1. Каждое сообщение идёт двумя прогонами. Планирование (LLM): kairon.route выбирает вид сообщения и область, страница строит план. Исполнение (сервер, шаги LLM отмечены): план для этого вида.
  2. Новый сценарий открывает раздел S1, S2… Смена цели строит дочерние черновики (v2 → v2.1). Вопрос отвечает по фактам без пересчёта.
  3. Строку ленты можно раскрыть: статус, вызовы LLM с повторами, входной и выходной JSON шага.
  4. «Сохранить как черновик» создаёт одну неактивную версию прогноза в Kairon.
Под каждым ответом блок «Технические детали»: сырой запрос, tool calls с JSON-схемами входа, тела запросов к LLM, время до первого токена, сырые ответы, вызовы Kairon и полный таймлайн событий.
